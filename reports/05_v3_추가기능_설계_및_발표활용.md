# DaySpark v3 추가 기능: 요구사항·설계·발표 활용

> 기존 Word 보고서 2개는 v2 시점의 **참고용 작성 양식**으로 보존하였다. 이 문서는 v3 기능을 반영하는 추가 작성 자료이며, 실제로 수행한 테스트와 사용자 평가는 실행·검증 후에만 보고서에 반영한다.

## 1. 이번 버전에서 추가한 기능

| ID | 요구사항 | 구체적인 수행 흐름 | 데이터/담당 컴포넌트 |
|---|---|---|---|
| R-V3-01 | 목표 수치 설정 | 1~10000의 수치와 분·페이지·회·개·잔 단위를 설정하고 매일 진행량을 수동 추가한다. | `Dare.targetValue/targetUnit`, `ProgressLog`, `ProgressService` |
| R-V3-02 | 일정 변경/건너뛰기 | 반복 일정은 유지하면서 특정 날짜를 `SKIP` 또는 `ADD`로 덮어쓴다. 두 날짜를 바꾸면 연기도 표현할 수 있다. | `ScheduleException`, `PlanningService` |
| R-V3-03 | 목표별 상세 통계 | 목표마다 월간 달성률·연속 달성·이번 주 목표·집중 시간을 제공한다. | `/challenges/{id}` |
| R-V3-04 | 주간 목표 | 주간 완료 목표 0~7회를 별도로 설정하고 실제 완료 횟수와 비교한다. | `Dare.weeklyTarget`, `Completion` |
| R-V3-05 | 시각적 집중 타이머 | 원형 진행 표시, 집중 1~120분, 휴식 0~30분, 반복 1~10회, 일시정지/재개/중단 | `/focus`, `FocusSession`, `FocusService` |
| R-V3-06 | 집중 이력·집계 | 실제 집중 시간이 다 끝난 회차만 누적한다. 당일·주간·월간 분 및 회차 수를 통계와 달력에 반영한다. | `FocusSession`, `/stats`, `/calendar/day` |
| R-V3-07 | 타이머·수치 목표 연동 | 타이머를 완료했을 때 연결된 목표의 단위가 `분`이면 완료된 집중 분을 해당 날짜의 진행량에 더한다. | `ProgressService.focusEarned` |

## 2. 데이터 관계

- `Dare` 1:N `Completion` (한 날짜에 한 목표당 완료 1회)
- `Dare` 1:N `ProgressLog` (하루에 여러 수치 진행 기록 가능)
- `Dare` 1:N `ScheduleException` (한 목표/날짜에는 예외 1건)
- `Dare` 1:N `FocusSession` (집중 세션별 1건; 완료/일시정지/중단 상태)
- 포모도로의 휴식 시간은 **누적 집중 분에서 제외**한다. 미완료·중단한 집중 시간도 제외한다.

## 3. 상태 전이 및 엣지 케이스

1. 집중 세션: `RUNNING ↔ PAUSED`, `RUNNING → COMPLETED`(서버에서 누적 완료시간 충족 시), `RUNNING/PAUSED → CANCELLED`. 완료된 세션을 다시 완료해도 분을 재적립하지 않는다.
2. 서버 시간(`startedAt`, `pausedMillis`)을 사용해 완료 시간을 확인하므로 브라우저 타이머 속도나 탭 비활성화 여부에만 의존하지 않는다. 브라우저를 닫았다가 다시 열면 미완료 중인 세션을 복구할 수 있다.
3. 반복 횟수 및 휴식 진행 상태는 **현재 브라우저**에 유지한다. 브라우저를 닫은 사이에는 추가 회차를 자동 실행하지 않는다.
4. 예외 지정은 오늘 이후, 목표 기간 내에만 가능하다. 이미 완료한 날짜를 `SKIP`으로 바꿀 수 없다.
5. 주간 목표의 `회`는 **도전 완료를 저장한 날짜의 수**이다. 수치 목표를 충족하거나 포모도로 회차를 마쳤다고 도전 자체가 자동 완료되지는 않는다.
6. 기존 전체 Streak는 **실제 도전 완료가 있었던 연속 달력일** 기준이다. 쉬는 날을 자동 성공일로 간주하지 않는다. 목표별 Streak는 예정일을 기준으로 별도로 계산한다.
7. 현재 앱은 단일 사용자·단일 브라우저 기반 과제용 서비스다. 회원가입/권한 관리·외부 배포를 구현했다고 보고하면 안 된다.
8. *현재 알려진 제한:* 목표 반복 규칙을 사후 수정하면 과거 예정 분모가 새 규칙으로 재계산될 수 있다. 과거 일정 스냅샷 기능은 미구현이다.

## 4. 중간발표와 기말발표에 사용할 내용

| 중간발표 (설계 증빙) | 기말발표 (구현·검증 증빙) |
|---|---|
| 핵심 사용자 시나리오: 수치 목표 → 포모도로 → 기록 | 실제 타이머 시작·일시정지·완료·취소 시연 |
| 타이머 상태 전이 다이어그램 | 완료/중단 회차의 DB 저장 비교 |
| 목표·예외일·세션 관계 ERD | 달력 및 목표별/전체 통계 연동 시연 |
| 요구사항 추적표 및 화면 프로토타입 | 자동 테스트 및 실제 사용성 피드백 (수행한 경우에만) |

## 5. 원본 참고자료와 양식 구분

- 보고서 전체 목차는 기존 `03_참고양식과_출처.md`에 기술한 Rutgers University Software Engineering Report #1·#2 구조를 **재구성하여 참고**했다.
- 반복적 프로토타이핑·시제품 개선 과정은 Stanford CS147 DareDrop 공개 산출물의 **구성 방식**을 참고했다.
- 실제로 프로젝트에서 수행하지 않은 인터뷰/사용성 평가를 수행했다고 기재하지 않는다.

## 6. 실제 실행·테스트 증빙 체크리스트

- [ ] Windows JDK 25에서 `00_START_DAYSPARK_CHROME.bat`으로 서버 기동 및 Chrome 자동 실행
- [ ] 목표 수치·주간 목표 저장 후 새로고침 유지
- [ ] 특정 요일에 도전 표시 및 SKIP/ADD 후 목록 변경
- [ ] 시작 → 일시정지 → 재개 → 종료 전에 완료 API 차단
- [ ] 한 회차가 끝났을 때만 완료 분·회차 수 증가
- [ ] 달력 날짜 선택 시 집중 분·완료 회차 확인
- [ ] 기존 사진·메모 업로드 및 도전 CRUD 정상 유지

**검증 상태:** 작성 단계의 체크리스트다. 체크되기 전에는 해당 항목을 실제 테스트 완료로 기재하지 않는다.
