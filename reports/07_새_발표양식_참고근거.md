# DaySpark 새 발표 양식 참고 근거

이번 패키지에는 기존 Word 보고서 양식을 유지하면서, 실제 발표에 바로 쓰기 쉬운 PowerPoint 양식을 새로 추가했다.

## 참고한 공식 소프트웨어공학 발표 지침

1. Calvin University CS 262 — Design Presentation
   - 핵심 구성: Vision, Analysis & Design, Demonstration, Status Report, Q&A
   - DaySpark 중간발표 양식의 기본 골격으로 사용
   - URL: https://cs.calvin.edu/courses/cs/262/kvlinden/15project/project4.html

2. Calvin University CS 262 — Final Presentation
   - 핵심 구성: Vision, Design, Demonstration, Assessment, Q&A
   - DaySpark 기말발표 양식의 기본 골격으로 사용
   - URL: https://cs.calvin.edu/courses/cs/262/kvlinden/15project/project7.html

3. Rutgers Software Engineering Project Demo
   - 핵심 지침: 최대 5장 개요 후 실제 시연 중심, 핵심 Use Case 위주, 로그인 같은 부가 기능보다 본질 기능 강조
   - DaySpark 시연 순서와 데모 로드맵 슬라이드에 반영
   - URL: https://eceweb1.rutgers.edu/~marsic/Teaching/SE/demo1.html

4. Rutgers Report #1 — System Specification
   - 핵심 구성: 문제 정의, 요구사항, 유스케이스, UI 명세
   - DaySpark 요구사항·유스케이스 슬라이드와 기존 Word 중간보고서 양식에 반영
   - URL: https://eceweb1.rutgers.edu/~marsic/Teaching/SE/report1.html

## DaySpark에 맞춘 적용 방식

- 중간발표는 Calvin의 Design Presentation 구조를 따라 `문제-요구사항-설계-초기 시연-남은 계획`으로 구성한다.
- 기말발표는 Calvin의 Final Presentation 구조를 따라 `최종 설계-주요 기능-실제 시연-테스트-평가`로 구성한다.
- Rutgers Demo 지침에 맞춰 발표 중 소스코드 설명은 최소화하고, 사용자가 보는 화면과 핵심 Use Case를 먼저 보여준다.
- Word 보고서는 제출이 필요할 때만 보조 자료로 사용하고, 기본 제출물이 PPT라면 새 PPTX 양식을 우선 사용한다.
