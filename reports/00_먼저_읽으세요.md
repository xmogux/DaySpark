# DaySpark 보고서 패키지 — 먼저 읽으세요

이 폴더는 **기존 DaySpark v2 코드를 바꾸지 않고** 소프트웨어공학 과제용 문서만 추가한 것입니다.

## 파일 안내
- `01_DaySpark_요구사항_중간보고서_양식.docx`: Rutgers Report #1 기반으로 *재구성*한 중간보고서 편집 양식.
- `02_DaySpark_설계_최종보고서_양식.docx`: Rutgers Report #2 기반으로 *재구성*한 설계·최종보고서 편집 양식.
- `03_참고양식과_출처.md`: 무엇을 어디에서 참고했는지, 인용 문구 예시.
- `04_프로토타이핑_개선기록_양식.md`: Stanford DareDrop의 반복적 사용자 중심 설계에서 참고한 작업일지 양식.
- `requirements_traceability.csv`: 요구사항 → 유스케이스 → 코드 → 테스트 연결표.
- `test_cases.csv`: 테스트 수행 기록(현재는 전부 미실행 상태의 작성 예시).
- `diagrams/*.mmd`: Mermaid 다이어그램 소스. 그림으로 렌더링해서 Word에 넣으세요.

## 문서 작성 순서
1. 교수님이 준 공식 양식·페이지 제한이 있으면 먼저 적용합니다.
2. 요구사항 Word에 문제 정의·유스케이스·화면 캡처를 실제 프로젝트 내용으로 채웁니다.
3. 설계 Word에 도메인 설계, 다이어그램, 구현 스크린샷을 붙입니다.
4. `mvn test`와 수동 테스트를 직접 실행한 뒤 CSV·보고서 결과를 채웁니다.
5. 실제로 하지 않은 설문·인터뷰·사용성 테스트는 절대 한 것처럼 작성하지 않습니다.
6. PDF로 제출해야 하면 완성한 Word를 직접 PDF로 내보내세요.
