# DaySpark 도메인 규칙

화면·통계·도메인 코드가 따라야 할 업무 규칙을 정리한 문서입니다.
일부 도메인 규칙은 단위테스트로 확인하며, 서비스 전체 흐름은 구현 코드와 별도로 점검해야 합니다.

## 1. 하루의 계획 (Day plan)

> 어떤 날의 **계획된 도전** = 그날 반복 규칙상 예정된 도전 **+ 그날 완료 기록이 있는 도전**

- 완료는 예정된 날에만 기록할 수 있으므로, 완료 기록은 "그날 계획되어 있었다"는 증거입니다.
- 그래서 나중에 반복 요일을 바꾸거나, 도전을 쉬거나, ADD 예외를 지워도 **완료 수가 계획 수를 넘지 않습니다**
  (달성률은 항상 0~100%).
- 오늘 화면, 달력, 날짜 상세, 통계, 도전별 달성률, Streak가 모두 이 규칙(`DareService.plannedFor`)을 씁니다.
- 구현 위치: `DareService.plannedFor`, `StatsService` (서비스 동작은 별도 확인 필요)

**알려진 한계:** 반복 규칙의 변경 이력은 저장하지 않습니다. 규칙을 바꾸면 *완료하지 않은* 과거 날짜의 계획 수는
새 규칙으로 다시 계산됩니다. → `docs/limitations.md`

## 2. 일정 예외 (SKIP / ADD / RESET)

| 동작 | 의미 | 제약 |
|---|---|---|
| SKIP | 이날 쉬기 | 오늘 이후, 도전 기간 안, **완료한 날짜는 불가** |
| ADD | 원래 일정이 없던 날 추가 | 오늘 이후, 도전 기간 안 |
| RESET | 예외 해제(원래 반복 규칙으로) | 오늘 이후, **완료한 날짜는 불가** |

- 완료한 날짜의 일정을 바꾸려면 먼저 완료를 취소해야 합니다.
- 구현 위치: `PlanningService.setOverride` (서비스 동작은 별도 확인 필요)

## 3. 완료와 완료 취소

- 완료는 **오늘 계획된 도전**에 대해서만, 도전·날짜당 한 번 기록합니다(DB 고유 제약 `dare_id + challenge_date`).
- 메모 최대 300자, 사진은 JPG/PNG/WEBP/GIF, 8MB 이하.
- **오늘의 완료는 취소할 수 있습니다.** 취소하면 완료 기록과 사진 파일이 함께 삭제되고, 그날의 계획은 그대로 남습니다.
- 구현 위치: `CompletionService.undo`, `ImageStorage` (파일 삭제 결과는 수동 확인 필요)

## 4. 수치 목표

- 도전마다 하루 목표 수치(1~10000)와 단위(분·페이지·회·개·잔), 주간 완료 목표(0~7회)를 가집니다.
- **목표량은 안내 기준이지 완료 조건이 아닙니다.** 진행량이 목표에 못 미쳐도 수동 완료를 허용합니다.
  (사진·메모만으로 완료하는 기본 흐름을 막지 않기 위해서)
- 구현 위치: `CompletionService.complete`, `ProgressService.add`

## 5. Streak (연속 기록)

`StreakCalculator`가 아래 규칙을 구현합니다.

1. 오늘부터 거꾸로 셉니다. 오늘 아직 달성하지 않았다면 어제부터 셉니다(진행 중인 오늘은 끊김이 아님).
2. **계획이 없는 날은 건너뜁니다.** (늘리지도 끊지도 않음)
3. 계획된 날을 달성했으면 +1, **달성하지 못한 첫 계획일에서 끝납니다.**
4. 가장 이른 시작일 이전은 보지 않고, 최대 366일까지만 봅니다.

| Streak | 계획된 날 | 달성한 날 |
|---|---|---|
| 전체 (오늘 화면·기록·통계) | 하루의 계획(규칙 1)이 1개 이상인 날 | **완료가 1개 이상**인 날 |
| 도전별 (도전 상세) | 그 도전이 계획된 날 | 그 도전을 완료한 날 |

- 전체 Streak는 "하루에 하나라도 해냈는가"를 보여주는 동기 부여 지표입니다. 그날의 모든 도전을 끝냈는지는
  달성률(%)이 보여줍니다.
- 단위테스트: `StreakCalculatorTest` (연속 기록 계산 규칙)

## 6. 복습 플랜

> 반복 수행 회차마다 복습을 만드는 것이 아니라, 사용자가 지정한 **하나의 학습 단위** 기준으로 복습 일정을 만든다.

- `STUDY` 카테고리 도전에서만 켤 수 있습니다.
- 사용자가 **복습 기준일**과 **간격(일)**을 직접 정합니다. 예: 기준일 10/2, 간격 `1, 3, 7` → 10/3, 10/5, 10/9 **총 3개**.
- 도전을 매일 반복·완료해도 복습 개수는 늘어나지 않습니다. 다음 단원으로 넘어가면 기준일을 바꿉니다.
- 간격은 1~3650일, 최대 12개. 입력은 정렬·중복 제거됩니다(`7, 1, 3, 7` → `1,3,7`). 전각 쉼표(`，`)도 허용.
- 기준일이나 간격을 바꾸면 기존 복습 완료 체크는 초기화됩니다(새 플랜과 섞이지 않도록).
- 복습 완료는 일반 도전 완료율·Streak에 포함하지 않습니다.
- 예정일 전에도 완료 표시를 할 수 있습니다(미리 복습 허용).
- **지난 복습은 완료할 때까지 오늘 화면에 남고** "N일 지남"으로 표시됩니다. 달력은 예정일 기준으로 보여줍니다.
- 도전을 쉬는 동안의 복습은 오늘 화면·달력에 표시하지 않습니다.
- 단위테스트: `ReviewIntervalsTest`, `DareScheduleTest` (간격·설정). 복습 조회·완료 흐름은 `ReviewService`에서 구현하며 별도 확인 필요.

## 7. 포모도로 연결 (집중 → 진행량 → 완료)

### 7.1 "실제 집중한 시간"과 "끝까지 완료한 세션"은 다르다 (v5.7)

| 세션 상태 | 언제 | 집중 시간(분) | 완료 횟수 | 진행량 · 자동 완료 |
|---|---|---|---|---|
| `RUNNING` / `PAUSED` | 진행 중 / 일시정지 | (아직 기록 전) | – | – |
| `COMPLETED` | 계획 시간을 끝까지 채움 | 계획 시간 전부 | **+1** | 아래 7.2 조건이면 반영 |
| `STOPPED` | **종료 및 기록** 또는 **도전 전환**으로 중간에 끝냄 | 실제 집중한 시간 | 0 | 반영 안 함 |
| `CANCELLED` | v5.7 이전의 "중단", API `/cancel` | 0 (버림) | 0 | 반영 안 함 |

1. **실제 집중한 시간** = 시작부터 끝까지의 시간 − 일시정지한 시간. 계획 시간을 넘지 않습니다.
   예) 25분 타이머를 12분 만에 종료 → 오늘·이번 주·이번 달 집중 시간 +12분, 완료 횟수 +0.
2. 세션마다 **1분 미만은 버리고** 분 단위로 기록합니다. 모든 합계(오늘·주·월·카테고리·달력 칸)는
   세션별 분의 단순 합이라 화면끼리 숫자가 어긋나지 않습니다.
3. **일시정지** = 멈추기만 합니다. 기록되지 않고, 일시정지한 시간은 집중 시간에 넣지 않습니다.
   일시정지 상태에서 종료하면 **일시정지 직전까지**만 기록합니다.
4. **종료 및 기록**(`POST /api/focus/{id}/stop`)은 세션을 끝내고 그때까지의 집중 시간을 남깁니다.
   계획 시간이 이미 다 지난 세션(예: 탭을 닫아 자동 완료가 안 된 경우)을 종료하면 **정상 완료(`COMPLETED`)**로 처리합니다.
   이미 끝난 세션에 다시 호출해도 결과가 같습니다(멱등).
5. **도전 전환**: 세션 중에 다른 도전을 고르면 "현재 집중 세션을 종료하고 다른 도전으로 전환하시겠습니까?"를 묻습니다.
   취소하면 그대로 진행, 확인하면 `POST /api/focus/switch`가 **한 트랜잭션에서** 이전 세션을 `STOPPED`로 기록하고
   새 도전의 세션을 시작합니다. 새 세션 조건(1~120분, 쉬는 중 아님, 다른 도전)이 맞지 않으면 아무것도 바꾸지 않습니다.
   휴식 시간에는 진행 중인 세션이 없으므로 다음 회차의 도전만 바꿉니다.
6. `STOPPED` 세션의 날짜는 집중이 끝난 시각(일시정지 중이었다면 일시정지 시작 시각)의 날짜입니다.
7. 기록된 세션(`COMPLETED`, `STOPPED`)은 취소할 수 없습니다.

### 7.2 완료한 세션 → 진행량 → 자동 완료

1. 끝까지 완료한 세션(`COMPLETED`)만 진행량에 더합니다. 도전의 목표 단위가 `분`이고
   **세션이 끝난 날짜에 그 도전이 계획되어 있을 때만** 더합니다.
   예정 없는 날의 집중은 정상 종료되고 집중 시간으로는 남지만, 진행량·완료에는 반영하지 않습니다.
2. 세션의 날짜는 계획 시간이 끝난 시각의 날짜입니다. 23:50에 25분 시작 → 다음 날 00:15 → **다음 날** 기록.
3. 진행량(직접 입력 또는 집중)이 **목표량에 처음 도달하는 순간** 자동으로 완료합니다
   (메모: "목표량 달성으로 자동 완료"). 이미 완료했거나 계획이 없는 날이면 아무것도 하지 않습니다.
4. 자동 완료를 취소한 뒤 진행량을 더 쌓아도 다시 자동 완료하지 않습니다(이미 도달한 목표). 수동 완료는 가능합니다.
5. 자동 완료는 예외를 던지지 않으므로 **세션 종료(finish)가 자동 완료 때문에 실패하지 않습니다.**
   finish는 같은 세션에 여러 번 호출해도 결과가 같습니다(멱등).
6. 브라우저는 finish가 실패하면 서버의 현재 세션 상태로 다시 맞추고, 5초 뒤에만 재시도합니다.
   (이전에는 실패 시 6초 동안 finish를 1,000번 넘게 호출했습니다.)

- 단위테스트: `FocusSessionUnitTests` (9개), `FocusServiceUnitTests` (2개). 서비스의 진행량 반영 여부는 Mockito로 확인하며 실제 데이터베이스 동작은 별도 확인 필요.
