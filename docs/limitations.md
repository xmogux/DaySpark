# 한계와 범위 결정

수업 프로젝트 기간과 "기능 수보다 일관성·테스트·설계 설명"이라는 목표에 맞춰 **일부러 하지 않은 것**과 그 이유입니다.

## 1. 범위에서 뺀 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 회원가입·로그인·다중 사용자 | 하지 않음 | 개인용 습관 앱으로 범위를 정함. 대신 서버를 `127.0.0.1`에만 열어 같은 Wi-Fi의 다른 사람이 접속할 수 없게 함 |
| CSRF 보호(Spring Security) | 하지 않음 | 로그인이 없는 로컬 전용 앱이라 우선순위 낮음. 외부 공개 시 필수 |
| Docker | 쓰지 않음 | Spring Boot 단일 앱 + 내장 H2라 JDK와 Maven Wrapper만으로 실행 가능. 컨테이너가 해결할 문제가 없음 |
| 알림·SNS 공유·AI 추천 | 하지 않음 | 핵심 흐름(계획 → 실행 → 기록 → 복습) 일관성이 우선 |
| Anki/SM-2식 자동 복습 간격, 습관 강도 점수, Streak 프리즈, CSV 내보내기, 히트맵 | 하지 않음 | 복습은 "사용자 지정 플랜"으로 의도를 고정함([domain-rules.md](domain-rules.md) 6절). 새 기능보다 기존 기능 간 규칙 일치가 우선 |
| 지난 날짜 완료 입력(소급 체크) | 하지 않음 | 완료는 "오늘"만, 취소도 "오늘"만 — 대칭을 유지. 잊은 날은 기록하지 않는 것으로 정함 |

## 2. 알고 있는 기술적 한계

### 2.1 N+1 쿼리 (최적화하지 않음)

화면을 그릴 때 날짜마다, 도전마다 일정 예외를 조회합니다. 도전 10개 · 기록 200일 기준으로 저장소 호출 수를 세면:

| 화면 | 저장소 호출 수 |
|---|---:|
| 오늘 | 29 |
| 도전 상세 | 6 |
| 통계 | 155 |
| 달력(한 달, 6주 격자) | 413 |

(작성 환경의 메모리 저장소로 측정. JPA에서는 대부분 1호출 = SQL 1개)

- **최적화하지 않은 이유:** 단일 사용자 로컬 H2라 체감 지연이 없고, 최적화(기간 단위 일괄 조회 + 메모리 계산)는
  `PlanningService.isScheduled`의 단순한 규칙을 복잡하게 만듭니다.
- **개선 방향:** `StatsService`에서 기간의 일정 예외·완료를 한 번에 읽어 `Map<(도전, 날짜), …>`로 계산.
  모든 계산이 `StatsService`에 모여 있어 이 클래스만 고치면 됩니다.

### 2.2 반복 규칙의 변경 이력을 저장하지 않음

반복 요일을 바꾸면 **완료하지 않은** 과거 날짜의 계획 수는 새 규칙으로 다시 계산됩니다.
완료한 날은 "하루의 계획" 규칙 덕분에 계속 계획으로 남아 달성률이 100%를 넘지는 않습니다.
정확한 과거 통계가 필요하면 규칙을 기간별로 저장(`dare_schedule_versions`)해야 합니다.

### 2.3 데이터베이스와 스키마

| 항목 | 현재 | 이유 / 대안 |
|---|---|---|
| DB | H2 파일(`dayspark_v2.mv.db`) | 설치 없이 실행. 여러 사용자면 PostgreSQL 등 |
| 스키마 변경 | `ddl-auto=update` + `columnDefinition` 기본값 | 프로토타입에 충분. 컬럼 삭제·이름 변경은 못 함 → Flyway 같은 마이그레이션 도구 필요 |
| `review_records.dare_id` | 외래 키 제약 없이 값만 저장 | 다른 테이블은 `@ManyToOne`. 삭제는 `DareService.delete`가 직접 정리함. 통일하려면 `@ManyToOne`으로 변경 |
| enum 컬럼 | 문자열로 저장, 경계에서 `DareCategory.parse` 등으로 검증 | 기존 v5.x DB 데이터와 호환 유지. `@Enumerated(EnumType.STRING)`로 바꿔도 값은 같음 |

### 2.4 그 밖의 한계

- Streak는 최대 366일까지만 셉니다(`StreakCalculator.MAX_LOOKBACK_DAYS`).
- 주간 목표(`weeklyTarget`)는 표시용입니다. "주 3회 아무 날이나" 같은 반복 규칙은 아닙니다.
- 집중 타이머는 브라우저 탭이 열려 있어야 화면이 갱신됩니다(시간 계산은 서버 기준이라 정확함). 종료 알림·소리 없음.
- 카테고리는 화면에 영문 enum 이름(STUDY 등)으로 보입니다.
- Spring Boot 3.5.x는 2026년 6월에 OSS 지원이 끝난 마지막 3.x 계열입니다(마지막 릴리스 3.5.16).
  수업 기간 안에 4.x로 올리는 것은 범위 밖으로 둡니다.
- 통합 테스트는 H2 메모리 DB에서 돕니다. 실제 파일 DB와의 차이(동시 접근 등)는 검증하지 않습니다.
